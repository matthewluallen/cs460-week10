CS460 · Weeks 10–11 Logic Studio · Circuit Studio · Analyzer UX & learnability
Design review + working prototypes

Can a novice and a controls engineer share one tool?

The platform is powerful and, in places, genuinely beautiful. The risk isn't capability — it's that a first-time student and a seasoned engineer need opposite things from the same screen. This review grades each surface, then proposes two concrete fixes you can try right here on the page.

The verdict, up front

Where each surface stands

Three ratings: Solid (keep it, polish only), Refine (clear, targeted improvements), Rework (structure is fighting the learner). Nothing here needs a ground-up redesign — the bones are good. The gaps are concentrated in onboarding, density, and consistency.

Who's actually at the keyboard

Two students, opposite needs

Every design call below is judged against these two. When a change helps one and hurts the other, that's the real design problem — and the reason "add a mode," not "pick a side," is usually the answer.

Novice · first PLC ever

Priya — CS / informatics student

Strong on code, new to ladder logic, relays, and buses. Here to understand how software reaches into the physical world — and to not feel stupid doing it.

  • Needs: one obvious next step, plain words before jargon, a small number of choices on screen at once.
  • Breaks on: a palette of 21 instructions, %IX0 / ABI v4 with no gloss, three stacked control bands, a greyed-out button with no reason.
  • Win condition: builds a working rung in the first ten minutes without reading a manual.
Expert · works with real PLCs

Dale — controls / automation engineer

Has wired hundreds of panels. Wants density, speed, and honest feedback. Hand-holding is friction. (A real instructor in this seat once said "I cannot find a way to make it run.")

  • Needs: everything reachable fast, keyboard shortcuts, ladder↔ST fidelity, the register table docked, not buried.
  • Breaks on: hidden RUN-readiness, a modal that hides live values, progressive disclosure that slows him down.
  • Win condition: loads, runs, and debugs without the UI ever getting in the way.
The principle that resolves it

Depth on demand, not depth by default. Show Priya a calm, minimal surface with an obvious path; let Dale summon full density with one click and have it stick. Same tool, two throttle settings — plus one consistent visual language so moving between Logic, Circuit, Protocol, and the Analyzer never feels like switching apps.

Surface by surface

What's working, what isn't

Logic Studio — the ladder / ST editor

Refine

The core is strong: editor-first layout, true ladder↔ST↔IL correspondence with live cross-highlighting, an honest register table, and now a full instruction set that runs on the real device IR. The problems are at the edges.

Finding · density

The instruction palette just doubled — straight into overwhelm

Adding timers, counters, edges, analog math and PID grew the insert row from ~7 buttons to 21. For Dale that's power; for Priya it's a wall she has to decode before she can place a single contact. This is the single most actionable regression from the new work, and it's fixable without removing anything. See the first prototype below.

Finding · wayfinding

"What do I do next?" is invisible — it stumped an expert

The Open → Validate → Connect → Load → Read → RUN sequence exists only as faint status text. RUN refuses with a reason in an easy-to-miss log line. A persistent, stateful workflow rail — with each disabled action explaining itself — serves both personas at once. See the second prototype.

Finding · scaffolding

Jargon arrives before meaning

%IX0, %QW0, ABI v4, "mirror coil" appear with no first-encounter gloss. A one-line plain-language tooltip on first hover (and a dismissible "beginner captions" toggle) would let Priya read the screen without diluting it for Dale.

Keep

The dual-language cross-highlight is the platform's best teaching asset

Hovering a rung element and watching the matching ST / IL light up is exactly how a novice builds the ladder↔text mental model. Protect it; make it more prominent, not less.

Circuit Studio

Solid

"Three paths → one point map → outputs" is a genuinely good piece of information design: hardwired DI, analog expansion, and Grove sensor on the left; the StamPLC point map as the single meeting point; relays on the right. It teaches the model, not just the pins. Minor: the empty live values (0.00 V) could read as an inviting "connect the twin to see these move" state rather than flat zeros.

Flow view

Solid

Field → bus → logic → bus → output, with the network plane (HMI/SCADA over Modbus) drawn above the bus plane acting on the same points. This is the "follow the signal" idea made literal, and it's the clearest explanation of the network-vs-bus distinction anywhere in the system. Leave it alone.

Protocol Studio (standalone)

Solid — the north star

Spacious, staged, modern: the "Follow the signal" hero, the single-line substation diagram, evidence-provenance tiles, a play-sequence. This is what a launched product looks like. It's also the yardstick: the rest of the system should borrow its spacing, hierarchy, and calm — that's the consistency fix below.

Logic / bus Analyzer

Refine — concrete bugs first

Fix the objective bugs before any styling:

• the "DEMO · synthetic data" badge overprints the time-axis labels (unreadable);
• the decode table's Val column — the most important one — is clipped off the right edge;
• Inject / Monitor flyouts cover the decode table, so you attack the bus blind;
• colour is load-bearing and colour-only (Start/Addr/Data/Stop, SDA/SCL) — fails WCAG 1.4.1;
• the auto-start tour traps pointer events on first load.

None of these are redesigns — they're a focused fix list. The analyzer's MITRE ATT&CK-ICS mapping (T0855 / T0830 / D3-PMAD) is rare and excellent; protect it.

The system as a whole — wayfinding & consistency

Refine

The design maturity is uneven: Protocol Studio is a finished product; Logic Studio is a dense instrument; the Analyzer is a capable prototype with rough edges. Moving between them, a student re-learns the layout each time. Two cheap wins: (1) one shared shell — same header, accent discipline, spacing scale, and a single "you are here" switcher across all tools; (2) a one-screen map of how the tools connect (logic makes the signal → the bus carries it → the analyzer reads it → the threat map explains the attack) as the novice's entry point.

Prototype 02 · try it

A workflow rail that answers "what next?" — and "why not?"

The same six-step path, made persistent and stateful. The current step is lit, finished steps are checked, and the one primary action per state explains itself when it can't run. Toggle the mode and the controller state to see it react.

WORKFLOW + mode identity · live prototype
MODE

One primary action per state (the colour is the mode — calm blue to author, green to monitor, a deliberate red to run real relays). A disabled action never just greys out; it says the one thing standing in the way. Dale gets his missing RUN button back; Priya always knows the single next move.
