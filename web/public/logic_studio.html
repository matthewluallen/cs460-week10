PROGRAM, RUN, REMOTE and reboot behavior

PROGRAM stops application scans and inhibits commanded outputs. It is the mode for local USB loading and recovery. It is a software state, not electrical isolation or an emergency stop; a commanded off state is not universally safe for a process.

RUN executes the installed application when its required sources are ready. Download is locked in RUN. RUN is not a network security boundary: accessible services and the selected vulnerable/secure firmware profile still determine which requests are accepted.

REMOTE also executes the application. It relaxes the core remote-download acceptance gate and satisfies the secure build’s Modbus-write mode prerequisite; it does not authenticate clients. The current project loader still uses trusted USB, and the legacy HTTP upload endpoint is a stub. Other legacy HTTP, DNP3 and IEC paths have their own checks. The optional host point policy restricts requests further; a rule never overrides existing mode, write or force restrictions.

Reboot defaults to PROGRAM. Insert the explicit Reboot RUN startup rung, or add TBD_STARTUP(MODE := RUN); before PROGRAM StudioProgram in Edit ST, to request RUN after the saved project is restored. This Studio declaration is outside scan logic. Readiness must pass within 30 seconds; otherwise the controller stays in PROGRAM. A new load still stays in PROGRAM. An explicit mode/stop request or fault cancels the current pending start; remove the directive and reload to change future boots.
