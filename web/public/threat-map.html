Threat Map — connecting the lab to the MITRE taxonomies

Every weakness you exercise on the StampLC maps onto the same public frameworks a real OT security team uses. This page ties each lab attack across seven taxonomies — the embedded threat (EMB3D), the code weakness (CWE), the attack pattern (CAPEC), the ICS technique (ATT&CK for ICS), how a red team emulates it (CALDERA), the defensive countermeasure (D3FEND), and — where an AI/ML surface exists — ATLAS.

IDs link to the official framework entry. Frameworks: EMB3D (emb3d.mitre.org), CWE (cwe.mitre.org), CAPEC (capec.mitre.org), ATT&CK for ICS (attack.mitre.org), D3FEND (d3fend.mitre.org), CALDERA / caldera-ot (github.com/mitre), ATLAS (atlas.mitre.org). ATLAS is N/A for all eight — none involve a machine-learning model today; if the course adds an ML anomaly detector on the sensor stream, the phone-sensor false-data attack would then map to ATLAS AML.T0043 (Craft Adversarial Data). CALDERA reality check: caldera-ot ships six protocol plugins (modbus, bacnet, dnp3, profinet, iec61850, gems) — only the two Modbus attacks have a real public plugin; MQTT, credential, overflow and RE attacks need a custom ability. Mappings are teaching approximations for CS460 Week 10, not an official crosswalk.
